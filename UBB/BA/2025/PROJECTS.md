
# Project Description Guidlines

When creating descriptions for assignments, follow these guidelines to ensure clarity, consistency, and completeness:

## 1. Assignment Categorization

- Clearly identify if the assignment is individual or group-based
- Include a brief title that reflects the assignment's nature
- Specify if students can mark the assignment as complete manually

## 2. Project Requirements

- Define the core deliverable (e.g., data visualization, dashboard, report, encourange the submission of single links with the project uploaded to GitHub)
- Specify data selection parameters:
  - Whether data sources are freely chosen or pre-assigned
  - Required data formats (e.g., row-based format)
  - Target data complexity (e.g., number of data points)
- Detail technical requirements:
  - Permitted tools and technologies
  - Required visualization characteristics (interactive vs. static)
  - Any specific technical constraints

## 3. Audience and Context

- Define the intended audience for the visualization
- Establish the presentation context (e.g., business pitch, academic presentation)
- Specify any role-playing elements (e.g., "acting as a data consultant")
- State assumptions about audience knowledge
- Empahsize the advantage of using local and/or personal datasets
- You generate in Hungarian, unless specifically instructed otherwise

## 4. Documentation Requirements

- Specify any required accompanying documents (reports, papers, etc.)
- Provide length or time parameters (e.g., reading time, word count)
- Outline required document structure and sections
- Detail any reflective components required

## 5. Presentation Format

- Specify presentation length with exact timing
- Detail presentation format and components
- State key questions that should be addressed
- Outline the expected narrative approach

## 6. Evaluation Structure

- Provide complete breakdown of grading percentages
- Specify all evaluation contributors (instructor, peers, team members)
- Detail any peer evaluation components
- Explain evaluation criteria

## 7. Administrative Details

- Include clear deadlines with date and time
- Specify submission method and platform - prefer single links, on GitHub
- Detail submission format requirements
- For group assignments, clarify submission responsibilities

## 8. Differentiation Between Assignment Types

- For courses with multiple assignment types, highlight key differences
- For group assignments, include team formation guidelines
- For individual assignments, emphasize personal analysis expectations
- Note different evaluation weightings between assignment types

## 9. Formatting Guidelines

- Use hierarchical organization with clear headings
- Group related requirements into logical sections
- Use bullet points and emojis for clarity
- Highlight critical requirements using bold or italic formatting

## 10. Grading format

- Projects are peer-graded, unelss specifically mentioned otherwise
- Datasets are free-choice, unelss specifically mentioned otherwise
- Groups are chosen freely, unelss specifically mentioned otherwise
- Any tool can be used, as long as it achieves the stated assignment objective
- Minimum required data complexity is usually 1000 data points with at least 3 dimensions
- Individual projects can include a presentation and a report
  - Reports do not have predefined length but should be readable in max 10 minutes
  - Presentations have a duration of 3 minutes + 2 minutes of questions
  - If a report is required, the grade breakdown is:
    - 40% report
    - 60% presentation, of which:
      - 30% peers - grades will be z-score normalized
      - 30% teacher
  - If no report is required, the breakdown is:
    - 50% peers - grades will be z-score normalized
    - 50% teacher
- Group rojects only include a presentation. The audience is a business setting.
  - Presentations have a duration of 5 minutes + 3 minutes of questions
  - If groups of more than 2, grade breakdown is:
    - 40% teacher
    - 40% peers - grades will be z-score normalized
    - 20% anonymous in-group rating - relative grades will be taken 
    into account and only if they differ
  - Memmbers of groups of two get equal grade.
    - 50% teacher
    - 50% peers - grades will be z-score normalized
